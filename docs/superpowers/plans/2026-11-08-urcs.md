# URCS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a buildable Android robotics-control application with honest real-device status and tested core logic.

**Architecture:** One Compose Android application module; isolate pure control/protocol/rule logic from Android sensor and transport adapters. Build vertical slices and document hardware-dependent limits.

**Tech Stack:** Kotlin, Jetpack Compose, Material 3, Android SDK API 26+, Coroutines/StateFlow, Gradle wrapper, JUnit.

**Spec:** `docs/superpowers/specs/2026-11-08-urcs-design.md`

## Global Constraints

- Package name: `com.robotics.urcs`.
- Minimum Android SDK: API 26.
- Never fabricate sensor values, connection states, or hardware test results.
- Keep phone emergency-stop best-effort and clearly caveated.
- APK target: `output/URCS-debug.apk`.
- Run requested unit tests, build, and lint when a toolchain is available; report exact blockers otherwise.

## Review Focus

- Android 12+ Bluetooth permission denial or API differences must not crash or show a false connection.
- Unsupported physical sensors must remain absent/unavailable and must not emit invented readings.
- Malformed network/protocol input must be rejected without blocking the UI or killing the session.
- Controller neutral/stop behavior must not keep sending movement after disconnect or emergency stop.
- Logging/export must handle empty data and CSV-special characters without corrupt output.

**Files:** Gradle wrapper/configuration, `app/src/main/AndroidManifest.xml`, `app/src/main/java/com/robotics/urcs/**`, `README.md`, progress ledger.

**Interfaces:** produces the app entry point and navigation shell for subsequent slices.

- [ ] Establish the Android project, version catalog or pinned dependencies, manifest, and Compose theme.
- [ ] Add navigable dashboard and nine requested destinations with meaningful empty/unavailable states.
- [ ] Add build instructions and a progress ledger.
- [ ] Build and run lint if toolchain is available.

### Task 2: Real sensor discovery and monitoring

**Files:** `sensors/AndroidSensorRepository.kt`, sensor UI/view-model files, manifest permissions, unit tests for pure formatting/selection logic.

**Interfaces:** exposes the actual device sensor list and lifecycle-scoped readings to the UI.

- [ ] Discover sensors from `SensorManager`; do not synthesize unsupported data.
- [ ] Register only while monitoring is active and unregister on lifecycle stop.
- [ ] Display metadata, values, units, accuracy, and unsupported status.
- [ ] Verify unit tests and Android build.

### Task 3: Communication and protocol core

**Files:** `communication/Transport.kt`, `TcpTransport.kt`, protocol codec, connection UI, parser tests, `HARDWARE_PROTOCOL.md`.

**Interfaces:** asynchronous connect/send/receive/state API; JSON command and telemetry codec.

- [ ] Test protocol parsing and invalid-message behavior before implementation.
- [ ] Implement TCP client with timeout, cancellation, readable errors, and no main-thread I/O.
- [ ] Expose actual transport state and terminal send/receive.
- [ ] Document tested versus untested adapters; add Bluetooth/USB only where verified.

### Task 4: Robotics controls and automation

**Files:** `robotics/MotionMapper.kt`, `automation/RuleEngine.kt`, controller/automation UI, focused unit tests.

**Interfaces:** bounded normalized motion commands, validated threshold rules, best-effort stop command.

- [ ] Test dead-zone, inversion, clamping, and emergency-stop gating first.
- [ ] Test rule validation, threshold evaluation, and disconnected-hardware guard first.
- [ ] Implement directional controls, speed, stop, and rule editor/status with actual connection gating.
- [ ] Keep phone stop explicitly distinct from hardware safety.

### Task 5: Local data, profiles, settings, and exports

**Files:** `logging/`, `profiles/`, `settings/`, tests, relevant UI, `TROUBLESHOOTING.md`.

**Interfaces:** local session entries, validated robot profiles, persisted appearance and sampling preferences.

- [ ] Test CSV escaping, profile validation, and setting defaults first.
- [ ] Implement local event/sensor logging, session display, and CSV/JSON export/share.
- [ ] Implement create/select/delete profile and real persisted settings.
